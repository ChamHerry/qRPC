## 1. 引言

### 1.1 目的
定义 qRPC 的测试分层、用例分类、工具、覆盖率与验收标准，保证跨语言一致性与高风险项（取消/背压/异步桥接）的正确性。

### 1.2 测试目标
- 验证 SRS 中所有 M（Must）级功能需求与关键 NFR。
- 保证 Rust↔Python↔Go 任意组合互通且语义一致。
- 对标 gRPC 的性能基准（0.2 出数，0.1 建立基线）。

## 3. 分层测试设计

### 3.1 单元测试（内核各模块，无网络）
| 模块 | 重点 | 手段 |
|---|---|---|
| `frame` | 帧编解码正确性、边界（空 payload、超长、畸形）、大端序 | 直接 encode/decode 对比黄金样本 |
| `call` | 状态机转换、各模式消息序 | in-proc 后端 + mock |
| `dispatch` | 方法路由、未知方法、handler panic 转 INTERNAL | in-proc |
| `error` | 状态码映射、STATUS 帧 | 单测 |
| `transport`（in-proc）| 抽象接口契约 | 直接测 |

### 3.2 集成测试（内核内）
- 用 in-proc 后端跑通 client→server 全链路（不经网络），验证 `call + frame + dispatch + conn` 协作。
- 覆盖四种调用模式。

### 3.3 跨语言一致性测试套件（⭐ 核心）
- **同一组 `.proto`**，运行所有 client×server 语言组合：
  - Rust↔Rust、Rust↔Python、Rust↔Go、Python↔Go、Python↔Python、Go↔Go（共 6 组）。
- **断言语义一致**：相同输入得到相同输出、相同错误码、相同超时/取消行为。
- 这套件是"全语言框架"质量的关键防线，对应 NFR-INTEROP。

### 3.4 端到端测试（真实网络）
- 用 quinn 后端，跨进程、真实 UDP/TLS。
- 覆盖：连接建立、多路复用、断连恢复、0-RTT（条件允许）。

### 3.5 性能 / Benchmark（0.1 建基线，0.2 对标）
- 用例：小包 Unary RPS、尾延迟（P50/P99/P999）、并发 stream 数、大消息吞吐。
- 对标：gRPC-over-TCP 同场景。
- 工具：criterion（Rust）+ 各语言自带 benchmark。

## 4. 高风险项专项测试（对应风险登记 R1–R3）

| 风险 | 专项测试 |
|---|---|
| R1 PyO3↔asyncio 桥接 | 高并发 asyncio 调用压测；GIL 下事件回调时序；线程安全唤醒 |
| R2 C ABI 跨语言背压一致性 | 三语言分别构造"慢消费"场景，验证不 OOM、正确限流 |
| R3 取消传播正确性 | client 取消 / 超时 / 断连 三类触发；断言 server handler 收到通知并清理（无 goroutine/task 泄漏） |

### 4.1 取消场景矩阵（必测）
| 触发 | client 行为 | server 断言 |
|---|---|---|
| client 主动 cancel | 调 cancel | handler 收到取消，清理资源 |
| 超时 deadline | deadline 到 | handler 收到取消，返回 DEADLINE_EXCEEDED |
| 连接断开 | 连接关闭 | 所有进行中 handler 收到取消 |

## 8. 覆盖率与质量门禁

| 指标 | 目标 |
|---|---|
| 内核行覆盖率 | ≥ 80%（0.1） |
| 跨语言一致性套件 | 6 组全绿 |
| 取消/背压专项 | 全绿 |
| panic/unwrap | 内核热路径禁用 panic（畸形输入优雅返回）|

---

## 9. 验收标准（0.1）

1. 所有 M 级 FR 测试通过。
2. 跨语言一致性 6 组组合全绿。
3. 取消场景矩阵与背压专项全绿。
4. 性能基线建立（小包 Unary RPS / 尾延迟有数据，不强求对标达标）。
5. 跨语言示例（Rust/Python/Go）可运行、文档可复现。
