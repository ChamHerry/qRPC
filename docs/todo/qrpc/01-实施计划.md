## 1. 实施结论

qRPC 0.1 是**绿地项目**（从零搭建），架构与 9 项设计决议已在 `docs/` 定稿。推荐实施路径：

1. **问题**：填补"原生 QUIC + 全语言"RPC 空白（gRPC 无原生 QUIC / IceRPC 仅 C# / quic-rpc 仅 Rust）。
2. **推荐路径**：**内核（Rust `core/`）先行 → 各绑定（Rust/Python/Go）并行 → 跨语言一致性测试收尾**。Monorepo 组织。
3. **最小风险切片**：先做 `T-001`（骨架）→ `T-002/T-003`（frame + TAL+in-proc）→ `T-005`（call 状态机，用 in-proc 验证 4 模式），**这一步即可验证内核架构是否成立**，再投入绑定。
4. **明确不做**：MsQuic/RDMA/TCP 后端、datagram、拦截器、lb、服务发现、健康检查、反射、更多语言、完整可观测性、C ABI 冻结（见 README §2.2）。
5. **LLM 起点**：从 `T-001` 开始。

## 4. 目标方案

### 4.1 目标链路

见 `docs/02-HLD §5`（Unary 端到端数据流）。

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 任务 |
|---|---|---|---|---|
| D-001 | Rust 内核 + C ABI + 薄绑定 | 内存安全 + gRPC C-core 验证 | C++ 内核（安全/开发成本） | T-001,T-010 |
| D-002 | quinn 首发 + TAL 预留 MsQuic | 小包高 RPS；TAL 可换栈 | 直接绑 MsQuic（开发慢） | T-003,T-004 |
| D-003 | protobuf 复用 + Codec 抽象（序列化在宿主语言） | 全语言生态红利 | 自研 IDL（工作量×N） | T-012 |
| D-004 | 每 RPC 一个 bidir stream | 享受 stream 独立性；与 gRPC 一致 | 连接复用自建多路复用 | T-005 |
| D-005 | 自研帧协议（8B 头，去 HTTP） | 去 HTTP 开销 | 走 HTTP/3 | T-002 |
| D-006 | gRPC 状态码 + STATUS | 迁移成本、跨语言一致 | 自研错误码 | T-008 |
| D-007 | 全局单一事件回调（call级）+ 连接级分离 | 跨语言回调复杂度最低 | 每操作回调 | T-010 |
| D-008 | Rust 绑定绕过 C ABI 直连内核 | Rust 一等公民 | Rust 也走 ABI | T-011 |
| D-009 | Monorepo | C ABI 联动 + 跨语言测试 | 多仓库（版本漂移） | T-001 |
| D-010 | 流控复用 QUIC 原生 + 背压上传 | 天然防 OOM | 自建流控 | T-005 |
| D-011 | 取消复用 STREAM_RESET + 传播清理 | 防 handler 泄漏 | — | T-005,T-010 |

> 协议层 5 项决议（D1-D5）、CABI 4 项决议（D1-D4）见 `docs/04-协议规范 §12`、`docs/05-CABI §10`，为实施硬约束。
