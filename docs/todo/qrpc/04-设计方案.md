## 2. 一句话方案

> 在 **Rust 内核 + C ABI + 各语言薄绑定** 的架构下，通过 **QUIC 原生传输（quinn 首发，TAL 可换 MsQuic/RDMA）** 与 **复用 protobuf 的代码生成**，填补"原生 QUIC + 全语言"RPC 空白；0.1 先打通 Rust/Python/Go 三语言端到端互通。

---

## 3. 核心架构（摘要，详见 `docs/02-HLD §2`）

```
宿主语言层(Rust/Python/Go 用户代码 + 各语言原生 protobuf 序列化)
        ── 代码生成层(protoc-gen-qrpc → stub)
        ── 绑定层(薄：Rust 直连 / Python PyO3 / Go cgo)
═══════════ C ABI(extern "C"，句柄+字节+元数据) ═══════════
内核(Rust)：RPC 协议层(call/frame/dispatch/error) + TAL + 后端(quinn/in-proc/…)
```

---

## 4. 已通过设计决议（硬约束）

- **协议层（`docs/04 §12`）**：D1 默认端口 7000；D2 COMPRESSED 不进 0.1；D3 client-streaming 半关闭+末帧 END_STREAM；D4 SETTINGS 不进 0.1；D5 消息上限 4 MiB。
- **C ABI（`docs/05 §10`）**：D1 不提供同步阻塞变体；D2 metadata 平行数组；D3 连接级回调与 call 级分离；D4 handler 按 service 注册。
- **架构（`docs/02 §3/§6.2`、`01 §4.2`）**：D-001~D-011（Rust 内核/C ABI/quinn/TAL/protobuf/stream 映射/自研帧/gRPC 状态码/事件回调/Rust 直连/Monorepo/QUIC 流控/取消传播）。
