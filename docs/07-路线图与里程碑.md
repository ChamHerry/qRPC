## 2. 各版本详细范围

### 2.1 v0.1「端到端打通」（当前）
**目标**：证明跨语言 + QUIC 原生 RPC 架构端到端跑通，三语言互通，早期用户可用。

| 层 | 交付 |
|---|---|
| 内核 | RPC 协议层（4 模式）、帧协议、TAL + quinn 后端、Connection Manager、Call 状态机、Dispatcher、错误/超时/取消/背压、C ABI、TLS 1.3 + 可选 token、最小 tracing |
| 绑定 | Rust 原生 crate、Python（PyO3）、Go（cgo） |
| 代码生成 | protoc-gen-qrpc（三语言 stub） |
| 示例/文档 | 跨语言互通示例 + 快速上手 |

**范围外**：MsQuic / RDMA / TCP 后端、datagram、拦截器、lb、服务发现、健康检查、反射、更多语言、完整可观测性。

### 2.2 v0.2「换栈验证 + 性能」
- ⭐ **MsQuic 后端**（验证 TAL 可换 + 高吞吐）。
- 性能优化与 benchmark（对标 gRPC，出正式数据）。
- 拦截器（interceptor）框架。
- 基础客户端负载均衡。

### 2.3 v0.3「生态扩展」
- 更多语言：Node（napi-rs）、C++、Java（JNI）。
- datagram 协同通道（差异化特性）。
- 健康检查、反射（gRPC reflection 式）。
- 可观测性完善（metrics / 分布式 trace 集成）。

### 2.4 v1.0「稳定承诺」
- ⭐ **C ABI 冻结**，公开向后兼容承诺。
- 生产就绪：健壮性强化、安全审计、文档完善、SLA 级别测试。
- 稳定 API（各语言绑定公开 API 冻结）。

### 2.5 v2.0「高端传输」
- ⭐ **RDMA 后端** + Cap'n Proto 零拷贝 codec（兑现 RDMA 价值，需端到端零拷贝贯通）。
- TCP 降级后端（提升连通性）。

## 3. v0.1 MVP 任务拆解（粗粒度，供实施计划细化）

任务按 Monorepo 目录组织（见 `02-HLD §6.2`）：

| # | 目录 | 任务 | 依赖 |
|---|---|---|---|
| T1 | `core/` | 项目骨架：内核 crate 分模块 + Cargo workspace + 顶层构建脚本骨架 | — |
| T2 | `core/src/frame` | 帧编解码 + 单测（黄金样本） | T1 |
| T3 | `core/src/transport` | TAL trait + in-proc 后端 + 单测 | T1 |
| T4 | `core/src/transport` | quinn 后端 | T3 |
| T5 | `core/src/call` | 调用状态机 + 四种模式 + 集成测试（in-proc） | T2, T3 |
| T6 | `core/src/dispatch` | server 方法路由 + server 骨架 | T5 |
| T7 | `core/src/conn` | 连接管理（池化/keepalive/断连） | T4 |
| T8 | `core/src/error` | STATUS + gRPC 状态码 | T2 |
| T9 | `core/src/(auth)` | TLS 1.3 + token | T4 |
| T10 | `core/src/abi` | C ABI 导出 + 全局事件回调（call 级 + 连接级） | T5,T6,T7,T8 |
| T11 | `rust/` | Rust 绑定（直连 core，一等公民 async API） | T5,T6 |
| T12 | `protoc-gen-qrpc/` | protoc 插件（三语言 stub 生成） | T11 |
| T13 | `python/` | Python 绑定（PyO3 + asyncio 桥接） | T10 |
| T14 | `go/` | Go 绑定（cgo + channel/context） | T10 |
| T15 | `tests/` | 跨语言一致性测试套件（6 组组合） | T11,T13,T14 |
| T16 | `tests/` | 取消/背压专项测试 | T15 |
| T17 | `tests/` | 性能基线 benchmark | T15 |
| T18 | `examples/` + `docs/` | 跨语言示例 + 快速上手文档 | T15 |

> 关键路径：T1 → T2/T3 → T5 → T10 → (T11 / T13 / T14 并行) → T15。
> 构建编排：`core/` 先行（Rust workspace），各绑定并行依赖 core 构建产物，跨语言测试收尾。

## 4. 风险登记（Risk Register）

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| R1 | PyO3↔asyncio 桥接（GIL、线程唤醒、事件时序） | Python 绑定可用性 | 高 | 早期做最小桥接原型验证；`pyo3-asyncio` 类方案；并发专项压测 |
| R2 | C ABI 异步模型跨语言一致性（三语言背压正确） | 全语言正确性 | 中-高 | in-proc + 跨语言一致性套件全覆盖；背压专项测试 |
| R3 | 取消传播正确性（边界多，易泄漏） | 资源泄漏/稳定性 | 中 | TDD；取消场景矩阵；资源/任务计数归零断言 |
| R4 | cgo 开销（Go 性能） | Go 性能 | 中 | 一次 send/recv 落在 cgo 边界、内部 channel 调度；benchmark 验证 |
| R5 | protoc 插件成熟度（schema 边界：oneof/streaming/metadata） | 代码生成质量 | 中 | 早期覆盖 gRPC 常用 schema；渐进补边界 |
| R6 | 范围蔓延（社区要求加功能） | 0.1 延期 | 中-高 | 明确 Out 清单 + 版本里程碑；贡献者按路线图引导 |
| R7 | QUIC 在 server-to-server 的 CPU 开销 | 服务端性能 | 中 | 定位云原生+客户端场景为基本盘；server 高吞吐靠 0.2 MsQuic + offload |

## 5. 成功标准（0.1）

1. **架构验证**：TAL 抽象经 in-proc + quinn 双后端验证完整。
2. **跨语言互通**：Rust/Python/Go 任意组合（6 组）一致性测试全绿。
3. **语义完整**：4 模式 + 错误 + 超时 + 取消传播 + 背压 全部可用并有测试。
4. **可用性**：跨语言示例可运行、文档可复现，外部用户能上手。
5. **性能基线**：小包 Unary RPS / 尾延迟有数据（对标数据 0.2 出）。
