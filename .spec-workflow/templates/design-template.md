**职责定义**：
- 接收请求参数
- 参数验证和转换
- 调用业务服务
- 组装响应数据
- 异常处理

**核心接口**：
```
[伪代码]
Interface Controller {

    handleCreate(request) -> response

    handleUpdate(id, request) -> response
    
    // 处理删除请求

    // 处理查询请求
```

**设计要点**：

## 4. 数据库设计
### 4.1 数据建模原则
- 遵循数据库范式（通常到第三范式）
- 适当的反范式化以提高查询性能
- 使用有意义的命名规范
- 添加必要的审计字段
- 考虑数据增长和扩展性

### 4.2 表结构设计
#### 4.2.1 核心业务表
```sql
-- 通用表结构模板
CREATE TABLE `table_name` (
    -- 主键
    `id` [主键类型] PRIMARY KEY,
    
    -- 业务字段
    `field1` [类型] [约束] COMMENT '字段说明',
    `field2` [类型] [约束] COMMENT '字段说明',
    
    -- 审计字段
    `created_by` [类型] COMMENT '创建人',
    `created_time` [时间类型] COMMENT '创建时间',
    `updated_by` [类型] COMMENT '更新人',
    `updated_time` [时间类型] COMMENT '更新时间',
    
    -- 逻辑删除（如需要）
    `is_deleted` [布尔类型] DEFAULT FALSE COMMENT '是否删除',
    `deleted_time` [时间类型] COMMENT '删除时间',
    
    -- 版本控制（乐观锁）
    `version` [数字类型] DEFAULT 0 COMMENT '版本号'
) COMMENT='表说明';

-- 索引设计
CREATE INDEX idx_field1 ON table_name(field1);
CREATE INDEX idx_created_time ON table_name(created_time);
CREATE UNIQUE INDEX uk_field2 ON table_name(field2);
```

### 4.3 索引设计策略
| 索引类型 | 使用场景 | 注意事项 |
|----------|----------|----------|
| 主键索引 | 唯一标识记录 | 自动创建，选择合适的主键策略 |
| 唯一索引 | 业务唯一性约束 | 避免过多唯一索引 |
| 普通索引 | 提高查询性能 | 基于查询模式创建 |
| 组合索引 | 多字段查询 | 注意字段顺序（最左前缀） |
| 全文索引 | 文本搜索 | 适用于大文本字段 |

### 4.4 查询优化建议
- **避免全表扫描**：合理使用索引
- **减少数据传输**：只查询需要的字段
- **批量操作**：减少数据库交互次数
- **分页优化**：使用游标分页代替偏移量
- **查询缓存**：利用缓存减少数据库压力
- **读写分离**：主从架构分担负载

## 6. 性能优化设计
### 6.1 性能指标
| 指标 | 目标值 | 监控方式 | 优化策略 |
|------|--------|----------|----------|
| 响应时间 | < 200ms (P99) | APM工具 | 缓存、索引、异步 |
| 吞吐量 | > 1000 QPS | 压测工具 | 负载均衡、集群 |
| 并发数 | > 500 | 系统监控 | 连接池、线程池 |
| CPU使用率 | < 70% | 系统监控 | 算法优化、缓存 |
| 内存使用率 | < 80% | 系统监控 | 内存管理、GC优化 |
| 错误率 | < 0.1% | 日志分析 | 容错、重试机制 |

### 6.2 缓存策略
#### 6.2.1 缓存层级
```
请求 → 浏览器缓存 → CDN缓存 → 应用缓存 → 数据库缓存 → 数据库
        ↓5ms        ↓20ms      ↓50ms      ↓100ms       ↓200ms
```

#### 6.2.2 缓存方案
| 缓存类型 | 适用场景 | 实现方式 | TTL策略 |
|----------|----------|----------|---------|
| 本地缓存 | 热点数据、配置 | 内存Map/LRU | 5-10分钟 |
| 分布式缓存 | 共享数据、会话 | Redis/Memcached | 10-30分钟 |
| HTTP缓存 | 静态资源 | ETag/Last-Modified | 1-7天 |
| 数据库缓存 | 查询结果 | 查询缓存 | 自动管理 |

#### 6.2.3 缓存更新策略
- **Cache Aside**：旁路缓存，应用管理缓存
- **Read Through**：穿透读取，缓存代理读
- **Write Through**：穿透写入，同步更新
- **Write Behind**：异步写入，延迟更新

### 6.3 数据库优化
#### 6.3.1 查询优化
- **索引优化**：创建合适的索引
- **SQL优化**：避免复杂JOIN、子查询
- **分页优化**：使用游标或LIMIT优化
- **批量处理**：批量插入、更新
- **预编译语句**：使用PreparedStatement

#### 6.3.2 连接池配置
| 参数 | 建议值 | 说明 |
|------|--------|------|
| 最小连接数 | 10 | 保持的最小连接 |
| 最大连接数 | 100 | 最大并发连接 |
| 连接超时 | 30s | 获取连接超时时间 |
| 空闲超时 | 600s | 空闲连接存活时间 |
| 验证查询 | SELECT 1 | 连接有效性检查 |

#### 6.4.2 限流策略
| 策略 | 实现方式 | 适用场景 |
|------|----------|----------|
| 固定窗口 | 计数器 | 简单限流 |
| 滑动窗口 | 时间窗口 | 平滑限流 |

### 6.5 异步处理
#### 6.5.1 异步模式
- **消息队列**：解耦、削峰、异步通信
- **任务队列**：后台任务、定时任务
- **事件驱动**：事件发布订阅
- **响应式编程**：非阻塞IO

#### 6.5.2 消息队列选型
| 特性 | 适用场景 | 常用方案 |
|------|----------|----------|

| 可靠性 | 交易、订单 | RabbitMQ |

| 分布式 | 微服务通信 | RocketMQ |

## 7. 安全设计
### 7.1 数据安全
- **敏感数据加密**：密码、密钥等敏感信息加密存储
- **传输加密**：HTTPS、TLS加密传输
- **数据脱敏**：日志、返回数据脱敏处理
- **SQL注入防护**：参数化查询、输入验证

### 7.2 访问控制
- **身份认证**：用户身份验证机制
- **权限控制**：基于角色的访问控制(RBAC)
- **接口鉴权**：API访问权限控制
- **数据权限**：行级、列级数据权限

### 7.3 其他安全措施
- **输入验证**：严格的输入参数验证
- **输出编码**：防止XSS攻击
- **CSRF防护**：Token验证机制
- **审计日志**：操作记录和追踪
